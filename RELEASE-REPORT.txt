ON Mission 16.48.0 — Resource Creation Idempotency Fix

Root cause: the Resources & Assets create form called /api/platform/admin/data-entry/reusable/preview without an Idempotency-Key header or body idempotencyKey. The server requires an idempotency key for prepareDataEntry and returned HTTP 400 DATA_ENTRY_IDEMPOTENCY_REQUIRED.

Fix: each create submission now generates a UUID idempotency key and sends it in both the Idempotency-Key header and request body. The same governed preview → step-up → commit → canonical reload workflow is retained. Release references are aligned to 16.48.0.

Checks: focused source-contract regression, JavaScript syntax, archive integrity, and single release-report checks. Live Cloudflare creation and persistence still require deployment verification.
