# ON Mission 16.9.2 — SQLite Build Failure Repair

## Root cause

The Cloudflare build used Node.js 24.18.0 successfully but failed in `scripts/check-runtime-schema-contract.mjs` because the build image's Python did not provide the `_sqlite3` module. The release check unnecessarily depended on a Python runtime separate from the declared Node toolchain.

## Repair

- Runtime SQL contract validation uses `node:sqlite` and checks each static SQL statement with `EXPLAIN`.
- Schema snapshot generation uses `node:sqlite`; regenerating `database/schema.current.sql` produced the same SHA-256 as the existing canonical snapshot.
- Four SQLite-backed mission certification tests use Node SQLite: reference scenarios, multisector certification, assignment capability, and mission continuity.
- Release commands explicitly enable `--experimental-sqlite` for compatible Node versions.
- The tests retain their SQL execution and assertions. No test was skipped or weakened to work around the missing Python module.
- No database migration was added. Migration high-water mark remains 0154. Do not rerun migration 0154 just to resolve the former build-time validation failure.

## Verification performed

- Runtime schema gate: **PASS — 1,324 SQL statements checked, zero failures**.
- SQLite schema generator: **PASS — 684 schema objects; canonical snapshot hash unchanged**.
- Four converted SQLite certification tests: **PASS**.
- Full `npm run check:release`: **PASS** in the available local Node 22.16.0/npm 10.9.2 environment.

## Still required

This environment does not match the project's declared Node 24.18.0 runtime, and dependencies were not installed here. Therefore a clean `npm ci`, production build/CSS compilation under Node 24, Cloudflare deployment, and live D1/runtime certification have **not** been claimed. Use the project's declared Node 24.18.0/npm 10.9.2 toolchain and `npm run deploy:production`; do not deploy with a direct `npx wrangler deploy` command.
