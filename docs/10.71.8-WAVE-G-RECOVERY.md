## Objective

Close the next remaining Wave G recovery boundaries without creating new domain authorities:

- make Trash lifecycle evidence failures explicit and recoverable;
- preserve canonical resource truth when evidence persistence is interrupted;
- keep restore/purge mutually exclusive through the existing mutation lease + SQL compare-and-set boundary;
- eliminate stale browser asset version references from the release pipeline;
- remove the remaining hard-coded 10.71.6 semantic release literal;
- strengthen final certification UI/runtime release integrity.

## Implemented

### Trash / Restore / Purge evidence

`platform_trash_items` now records:

- `evidence_status`: `complete | pending_reconciliation`
- `evidence_error_code`
- `evidence_updated_at`

Lifecycle evidence is handled by one helper. A lifecycle-event failure after a canonical Trash/Restore/Purge mutation no longer disappears through `.catch(()=>{})`. The canonical mutation remains authoritative and the response explicitly reports `pending_reconciliation`.

This is evidence state only; it does not become a second resource-state authority.

### Release asset convergence

The deterministic runtime-release generator now rewrites `?v=<release>` asset references under `public/` and `src/worker/` to the canonical `/VERSION` value. This prevents a new release from inheriting stale cache-busting references from the previous release.

### Semantic release convergence

The remaining hard-coded `10.71.6` Command Center metadata value was replaced with `RELEASE_VERSION`.
