# ON Mission 13.5.0 — Mission Outcome Engine + Execution Runtime Hardening

13.5 closes the operational loop from **ASSIGN → EXECUTE → EFFECT → VERIFY → OUTCOME** and prepares the platform for continuous mission operation.

## Canonical boundaries

- Mission truth remains owned by `mission_authority` / canonical mission lifecycle.
- Assignment truth remains owned by `mission_assignment_authority`.
- Execution intent and execution attempts remain owned by their existing authorities.
- Provider truth remains owned by provider integration.
- Verification remains owned by verification/recovery authorities.
- **Mission outcome is now one canonical derived authority**: `mission-outcome-authority.service.js` backed by append-only `mission_outcome_assessments`.
- Learning remains derived from outcomes and cannot mutate mission truth or authorization.

## Outcome semantics

`ACHIEVED` is only asserted when the canonical mission is terminal and sufficient canonical execution/evidence exists. `UNKNOWN` is never converted into success. Unresolved recovery or critical exceptions produce `BLOCKED`. Non-terminal verified effects produce `PARTIALLY_ACHIEVED` rather than pretending the mission is complete.

Each outcome assessment carries the mission objective hash, assignment, execution attempt, verification status, evidence, recovery summary, reasons and a next-situation recommendation.

## Runtime hardening

Every governed execution captures the current canonical assignment and version as a runtime fence plus a short lease. Immediately before the real canonical effect, the fence is revalidated. If the assignment changed or was revoked, execution fails closed instead of acting under stale responsibility.

Execution attempts also retain effect hashes, heartbeat/lease fields and retry count for durable operational reconciliation.

## Journey

`OBSERVE → UNDERSTAND → PLAN → POLICY CHECK → AUTHORIZE → PREPARE → ASSIGN → EXECUTE → VERIFY → RECOVER → OUTCOME → LEARN → NEXT SITUATION`

Assignment is part of PREPARE, while OUTCOME determines whether the mission objective was actually achieved and emits a bounded next-situation signal. No new sector-specific execution engine or duplicate assignment authority is introduced.
