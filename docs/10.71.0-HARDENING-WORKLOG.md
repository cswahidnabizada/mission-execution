## 10.71.3 — Wave G Adversarial Idempotency Hardening

Status: hardening candidate; source/release certification PASS.

### Finding
Mission creation previously claimed an idempotency key, created canonical mission truth, then finalized the idempotency row in a separate D1 write. If finalization failed after the mission existed, the error path could release the still-unfinalized claim. A client retry could then create a second mission for the same logical request.

### Fix
- Added `request_idempotency.resource_reference` and an index.
- Persist the allocated canonical mission reference immediately after the idempotency claim and before the canonical mission mutation.
- On duplicate retry, resolve an unfinalized claim by the durable resource reference and finalize it against the existing mission.
- Return explicit `reconciled:true` when retry recovery repairs the idempotency linkage.
- Added `check-10-71-3-adversarial-idempotency.mjs` and wired it into the complete release gate.
- Added migration 0120 and updated the current schema snapshot.

### Result
The idempotency path now follows:

claim → durable resource reference → canonical mutation → finalization
                         ↘ failure → retry reconciliation → existing truth

No duplicate mission is created solely because idempotency finalization failed after canonical creation.
