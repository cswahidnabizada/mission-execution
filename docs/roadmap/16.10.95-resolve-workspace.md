# 16.10.95 — Resolve Workspace

## Objective
Make the guided Market Launch flow an in-place execution workspace rather than navigation to a separate evidence card.

## Delivered in source
- A dedicated Resolve Workspace starts hidden until the user requests the next required task.
- The next incomplete task is promoted into the workspace, including its existing governed evidence editor.
- Stage/category context is retained so next-action guidance remains tied to the current task.
- The user can return the task to its original stage list.
- Evidence saves continue through the existing step-up-protected canonical task endpoint; the workbench refreshes canonical state after saving.

## Constraints
- No task is marked complete by navigation alone.
- No readiness, authorization, publication, or market activation gate is bypassed.
- This is the in-place task execution foundation. Multi-step task contracts, durable server-side resume, live browser validation, and deployed Germany Logistics certification remain separate follow-on work.

## Quality gates
Run focused resolve-workspace regression, JavaScript syntax, release integrity, dependency lock, migration contract, schema contract, and release-engineering checks. The Node.js 24 build and deployed authenticated browser certification remain required before production certification.
