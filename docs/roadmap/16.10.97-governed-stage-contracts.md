# 16.10.97 — Governed Stage Contracts and Launch Liveness

## Delivered in source
- Resolve renders a task-specific ordered substep contract in place, with an explicit owning-authority description.
- Product/resource tasks guide the user through find, inspect, reuse-or-create, configure, explicit market link, validate, and evidence.
- Legal, verification, release-transition, recovery, and general tasks receive tailored ordered guidance.
- Marking a task COMPLETE in the UI requires a substantive summary and traceable evidence reference; the canonical server remains the authority and can still reject the transition.
- Empty task lists explicitly require canonical readiness reassessment and do not imply market readiness.
- Task-save failures preserve the open task and show a retry-oriented error rather than silently moving on.

## Explicit limitations
- Substeps are guided UI contracts, not yet independently persisted server-side step records. They do not claim individual substep completion.
- The task authority labels are explanatory defaults; a canonical backend contract must eventually return exact authority identifiers, required evidence schemas, dependencies, and allowed commands.
- Server-side resume, authenticated browser verification, Node.js 24 build, full cumulative release suite, deployed runtime checks, and Germany Logistics pilot certification remain required before production certification.

## Safety invariants
- Never infer market readiness from an empty task list.
- Never mark COMPLETE without evidence fields in the UI; the server remains the final gate.
- Never silently create or link resources.
- Never bypass step-up authorization or the canonical Market Factory task endpoint.
- On failure, preserve the task context and name the recovery path.
