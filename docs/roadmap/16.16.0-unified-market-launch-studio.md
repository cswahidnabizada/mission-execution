# ON Mission 16.16.0 — Unified Market Launch Studio

## Product decision

The Super Admin's default landing workspace is now Market Launch Studio. The first-time workflow is one guided form and one market portfolio, not a sequence of unrelated navigation destinations. Advanced package import remains available but is secondary.

## Guided preparation inputs

- Country name and ISO code
- Product name and stable product key
- Primary language
- Sector name and stable sector code
- Intended data jurisdiction and primary region
- Billing currency
- Requirement selections for mission lifecycle, human roles, onboarding, mission workspace, responsive layout, AI drafting, Microsoft 365, and cloud/SAP integration

## Truth and security boundary

The form stages a market package using the existing step-up-protected Market Factory intake API. It does not directly mutate canonical country, sector, billing, identity, policy, provider, connection, tenant, AI, agent, robot or device authorities. Selections for integrations and experience are persisted as requirements, explicitly marked as needing canonical authority verification. Live secrets are never entered in this form. The existing immutable version and validate → authorize → publish → verify → activate lifecycle remains authoritative.

Tenants must not receive Super Admin authority. The product should reuse shared UI components and workflows in tenant context, but the server must resolve the authenticated tenant, scope every query and mutation to that tenant, enforce role/capability contracts, use consent and step-up where appropriate, and deny platform-wide routes to tenant identities. Simulator/device/robot actions require a separate sandbox or device capability grant and must never be implied by a UI checkbox.

## Remaining work (explicit)

- Replace package requirement markers with real registered adapters for every selected resource type and owning authority.
- Add server-side schema validation and semantic validation for all guided form fields and package dependencies.
- Implement real connections via provider-owned OAuth/secret flows; no client-supplied credentials.
- Complete legal review, Test Lab execution, mission effect and recovery evidence, and immutable release promotion.
- Build a tenant-scoped counterpart for authorized tenant workflows; do not expose Super Admin UI as a tenant login shortcut.
- Run Node 24 build, cumulative release suite, browser tests, deployed runtime tests and Germany Logistics pilot certification.

## Acceptance priorities

Security → Truth → Liveness → Stability → Experience → Scale.
Canonical journey: OBSERVE → UNDERSTAND → PLAN → EVALUATE → ACCEPT → AUTHORIZE → PREPARE → ASSIGN → EXECUTE → EFFECT → VERIFY → RECOVER → OUTCOME → LEARN → NEXT SITUATION → OBSERVE.
