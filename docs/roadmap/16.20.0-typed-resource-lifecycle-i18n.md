# ON Mission 16.20.0 — Typed Resource Schemas, Sector Lifecycle and Translation Assets

## Scope
- Resource Studio definitions expose field schemas with type, requiredness, enum options, constraints, and relationship hints.
- The guided editor renders booleans, integers, enums, text, JSON structures, and relationship references from those schemas.
- Sector lifecycle assets are stored as versioned canonical platform configuration records under `mission.lifecycle`, scoped to an existing active canonical sector. Lifecycle states require one initial state and at least one terminal state; transitions must reference known states and cannot leave terminal states.
- Translation bundles are versioned canonical platform configuration records under `i18n.catalog`, with locale/fallback metadata, direction, bounded translation keys/values, and no credentials/secrets.
- Resource Studio provides a server-authoritative dependency impact preview. The preview never grants mutation permission.
- Tenant Settings remain separate from Super Admin; this release does not yet ship complete tenant provider, AI, or physical-device execution adapters.

## Safety invariants
- Existing canonical configuration authority owns versioning and persistence; no second database authority is introduced.
- New assets go through Data Entry preview, canonical validation, step-up authorization, commit, and audit.
- No live resource is edited in place by these new asset types; configuration versioning remains the canonical service's responsibility.
- Impact preview is advisory; destructive actions still require the owning authority to re-check lifecycle and dependencies.
