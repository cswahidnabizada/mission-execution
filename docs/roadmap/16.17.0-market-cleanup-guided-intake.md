# ON Mission 16.17.0 — Market Cleanup and Guided Intake

## Intent
Reduce duplicate unfinished market records and make package intake understandable without sacrificing release history or canonical authority boundaries.

## Implemented
- Step-up protected `POST /api/platform/admin/market-factory/:packageId/delete-draft` endpoint.
- Exact typed confirmation token bound to package ID.
- Server-side deletion eligibility: package must be DRAFT, have no active version, all versions must remain in disposable pre-release states, and no publication operation may have started.
- Draft package/version coordination rows are removed through existing FK cascade behavior; package-level PREPARED publication operation rows are explicitly removed first.
- Audit intent is recorded before destructive mutation. A failed audit prevents deletion.
- Market portfolio cards show a deletion action only for DRAFT markets without active versions.
- Advanced JSON intake presents a minimal example and copy/edit-to-input actions.
- No schema migration.

## Explicit limits
This does not delete canonical country/sector/policy data because those resources may be shared by other markets. It does not delete progressed/published/live market history. Browser/deployed runtime certification and Node 24 build remain outstanding.

## Required verification
Syntax checks, focused static contract tests, release integrity, dependency lock, migration/schema checks, release engineering checks and ZIP integrity. Full cumulative suite and authenticated browser tests are separate required gates.
