# 16.10.94 — Adaptive Market Launch Workbench

Base: 16.10.93.

## Goal
Make Market Launch task-oriented and context-sensitive rather than displaying resource creation as a universal action.

## Changes
- Resource context starts hidden and is revealed only when the selected incomplete task's title, description or canonical category indicates a relevant resource domain.
- The create action remains hidden unless task language indicates a likely configuration, preparation, creation or missing-resource need.
- Existing resource search uses `/api/platform/admin/resource-search` and re-reads selected results through `/api/platform/admin/resource-explorer/:type/:id`.
- The in-workbench detail view is explicitly read-only. Governed edits/lifecycle actions remain in the owning Resource 360 workspace.
- The primary next action is summarized as one verb, such as CONFIGURE, REVIEW, APPROVE, VERIFY, RECOVER, PUBLISH or ACTIVATE, with the exact task immediately beside it.
- Resource creation, canonical market linking, evidence completion and launch lifecycle remain separate; no readiness or approval gate is bypassed.

## Safety / limitations
Client-side task wording is only a relevance heuristic. The canonical backend must remain authoritative for required resources, tenant scope, permissions, linkage, readiness and task completion. This release does not claim server-persisted stage resume or live Germany pilot certification.

## Verification
Focused regression covers adaptive visibility, canonical search and authoritative re-read. Full release suite, required Node.js 24 build, authenticated browser testing and deployed runtime certification must pass before production deployment.
