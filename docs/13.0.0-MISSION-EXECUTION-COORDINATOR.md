# ON Mission 13.0.0 — Mission Execution Coordinator

## Purpose

13.0.0 establishes one application-level execution conductor without creating another domain authority.

The coordinator sequences the governed mission journey:

OBSERVE → UNDERSTAND → PLAN → POLICY CHECK → AUTHORIZE → PREPARE → EXECUTE → VERIFY → RECOVER → OUTCOME → LEARN → NEXT SITUATION

## Boundary

The Mission Execution Coordinator is an application orchestrator. It does not own mission truth, authorization truth, provider truth, execution-attempt truth, or recovery truth.

Existing capabilities remain the owners of their contracts and canonical authorities.

## Capability separation

- Mission Truth: canonical mission state
- Situation Intelligence: current situation/context
- Planning: next-action plan
- Authorization: policy and execution authority
- Readiness: execution preconditions
- Execution: execution attempt and canonical action delegation
- Provider Integration: external-world operation
- Verification: effect verification
- Recovery: unresolved/failed effect reconciliation
- Outcome: verified result recording
- Learning: post-outcome learning
- Resource Governance: governed platform resources
- Platform Control: Super Admin governance

## Entry points

The canonical execution entry point is:

`POST /api/mission-execution/missions/:missionId`

The historical agent execution endpoint remains as a compatibility adapter but delegates to the Mission Execution Coordinator. It is not a competing execution authority.

## Permanent invariants

1. One mission execution conductor.
2. No coordinator-owned mission truth.
3. No coordinator-owned authorization truth.
4. No coordinator-owned provider truth.
5. UNKNOWN never means SUCCESS.
6. External effects require explicit verification before canonical effect commitment.
7. Capability outputs must remain structured and consumable by downstream capabilities.
8. Existing canonical authorities remain authoritative.
9. Sector-specific execution engines are prohibited; sector behavior is supplied through contracts/capabilities.
10. The coordinator must remain replaceable without changing canonical domain ownership.
