# ON Mission 13.1.0 — Verification + Recovery Convergence

## Purpose

13.1.0 converges Verification and Recovery into one governed application boundary beneath the Mission Execution Coordinator.

The objective is to ensure that a mission can only be considered successfully executed when the required evidence exists in the canonical authorities.

## Journey

OBSERVE → UNDERSTAND → PLAN → POLICY CHECK → AUTHORIZE → PREPARE → EXECUTE → VERIFY → RECOVER → OUTCOME → LEARN → NEXT SITUATION

13.1 specifically hardens the VERIFY → RECOVER segment.

## Architecture

Mission Execution Coordinator → Verification/Recovery Coordinator → existing Verification/Recovery authorities → Canonical Truth.

The 13.1 coordinator does not own mission truth, execution attempts, provider truth, or recovery truth.

## Verification rules

- Internal execution requires canonical-effect evidence.
- External and hybrid execution require provider verification AND canonical-effect verification.
- UNKNOWN is never SUCCESS.
- A canonical state match alone cannot prove an external side effect.
- A failed or unresolved external effect is not automatically replayed.

## Recovery rules

Recovery may:

- verify current canonical truth;
- reconcile provider evidence;
- classify the execution as unresolved;
- create a retry candidate for fresh planning/authorization;
- escalate for human review;
- record append-only recovery evidence.

Recovery may not silently mutate mission truth or become a second execution authority.

## 13.0 defect repaired

The governed execution error path previously referenced `intentRecoveryWrite` before initialization. 13.1 removes that temporal-dead-zone failure and preserves the original execution error while recording structured outcome-recording failure information.

## Permanent invariants

1. External execution requires provider evidence and canonical evidence.
2. Verification never promotes UNKNOWN to SUCCESS.
3. Recovery never auto-retries UNKNOWN without fresh evidence and authorization.
4. Recovery does not own canonical mission truth.
5. Execution intent remains an execution ledger, not mission truth.
6. One Mission Execution Coordinator remains the application-level execution conductor.
7. Historical execution endpoints remain adapters, not authorities.
