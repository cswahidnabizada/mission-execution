# ON Mission 11.17.0 — Customer Pilot Operating Model

## Purpose

11.17 introduces a bounded customer-pilot layer for proving ON Mission against real operational work before broad controlled autonomy. The pilot layer is deliberately outside canonical mission truth and execution authority.

## Pilot lifecycle

`DRAFT → READINESS → READY → ACTIVE → PAUSED → CLOSED`

A pilot is scoped by:

- company
- country
- sector
- operating mode
- approved action allowlist
- required provider codes
- operator role expectations
- explicit time window for controlled execution

## Controlled execution boundary

When platform and company autonomy are enabled for controlled execution, the governed execution service additionally requires:

1. an ACTIVE customer pilot;
2. the mission to belong to the pilot company;
3. the mission country and sector to match the pilot;
4. the mission to be explicitly enrolled;
5. the action to be in the mission's pilot allowlist;
6. the pilot execution window to be open;
7. all existing 11.16 autonomy, jurisdiction, provider, canonical readiness, authorization and verification gates to pass.

No pilot gate creates canonical truth or replaces canonical authorization.

## German launch packs

### Logistics — Germany

Reference scenario: `logistics.pickup-delivery.de`

Core operational sequence:

`ASSIGN → ARRIVAL → PICKUP → TRANSIT → DELIVERY → PROOF → COMPLETE`

Pilot candidates can be allowlisted individually, but assignment and completion remain human-authorized by the existing risk policy.

### Cleaning — Germany

Reference scenario: `cleaning.service.de`

Core operational sequence:

`ASSIGN → START → WORK / EXCEPTION → COMPLETE`

The cleaning contract is intentionally sector-specific at the reference layer while reusing the same canonical action, mission, authorization, evidence and recovery authorities.

## Real-world exception posture

The pilot layer never treats a timeout, provider failure, stale state, missing evidence, conflicting state or unavailable authority as success. Existing execution recovery remains responsible for UNKNOWN, partial effects and reconciliation.

## Global design

Germany is the first launch jurisdiction, not a platform hard-code. Country and sector are explicit pilot dimensions so later launches can introduce other jurisdictions and sectors without cloning the execution architecture.
