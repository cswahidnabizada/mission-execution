# 16.10.38 — Platform-Wide UI Consistency & Runtime Defect Elimination

## Purpose
Establish `public/assets/css/frontend/canonical-layout.css` as the shared structural layout contract for canonical platform and tenant work surfaces, including Market Factory. Feature styles remain responsible for component appearance and domain behavior; this file owns intrinsic sizing, overflow, responsive grid composition, and shared spacing tokens.

## Changes
- Extended shared structural rules to application, admin, tenant, resource, publisher, and market workspace composition.
- Applied the canonical stylesheet after component styles to primary platform/tenant HTML entry points.
- Added responsive market/product/release card grids using intrinsic sizing rather than fixed narrow columns.
- Standardized long-text wrapping, media sizing, form control width, and horizontally scrollable data tables.
- Added release-gated regression checks for canonical stylesheet coverage and market layout behavior.
- No domain authority, mission lifecycle, authorization policy, database schema, or market release state is changed by CSS.

## Cleanup policy
Do not bulk-delete CSS declarations merely because selectors repeat. Cascade order and selector specificity can be intentional. Retire competing rules only after the selector is traced to every consuming surface and a browser regression proves no behavior/layout loss. This release centralizes structural rules but preserves feature-specific skinning until a safe, evidence-backed retirement can be performed.

## Required certification
- `npm run check:release`
- `npm run build` with Node 24.18.0
- Browser checks at 1440px, 1024px, 768px, 390px and 320px
- Long IDs/text, empty/loading/error states, dense tables, market cards and release evidence grids
- Confirm navigation/actions and Market Factory authorization/publish lifecycle remain unchanged
